# Статическое освещение PS4

Обычный `LevelAssembler.assemble_chunk` теперь автоматически создаёт папку
`static_lighting` рядом с GLB/GLTF. Экспорт из просмотрщика также включает её в ZIP.
`blender_export.py` автоматически подключает карты, атрибуты и предварительные
материалы при импорте такого GLB или `scene.json`. Отдельный запуск команд ниже
нужен только для исследования или старых экспортов. Полная сборка Остина передаёт
данные освещения каждого чанка в общую сцену, сохраняя видимость стриминга.

Готовое освещение смотрите в `.blend` через Material Preview/Rendered. FBX сохраняет
доступные цветовые/UV-слои и custom properties, однако не переносит эту сложную
схему узлов Blender полностью; исходные карты и потоки остаются рядом в sidecar.
Если требуется точное освещение при повторном импорте, используйте `.blend`.

Извлечение работает по структурам PAK, без таблицы имён локаций. Проверено на
`hom-house-interior-tstrm.pak` и `hom-woods-hill-tstrm.pak`. Другие версии формата,
включая PC, не считаются автоматически поддержанными.

```powershell
python -m tlou_extractor.static_lighting 'D:\TLOUPS4\Extracted\pak32\hom-house-interior-tstrm.pak' --output 'D:\TLOUPS4\StaticLighting\house'
```

Можно передать несколько PAK перед `--output`. Выход:

- `lighting.json`: источник, полный идентификатор меша, контрольные суммы геометрии,
  размеры потоков, точные хеши слотов освещения, предупреждения.
- `streams.bin`: исходные float32-данные атрибутов 5, 8, 9 и 10 для каждого экземпляра.
- `<hash>.dds`: десвиззленный старший доступный mip с исходным форматом, в том числе
  BC6H HDR. Карты с одинаковым именем из разных локаций не смешиваются.

## Что подтверждено

GEOMETRY_1 ссылается на экземпляры через +0x48/+0x50. Экземпляр размером 192 байта
содержит число записей мешей по +0x20 и указатель по +0x30. Запись меша размером
80 байт содержит имя по +0, число потоков по +0x10 и таблицу потоков по +0x18.
Дескриптор потока размером 24 байта: stride +2, size +4, компонент +8, данные +16.
Это данные экземпляра: прототип содержит нулевые потоки и индексы-заглушки.

Материалы содержат g_tLmBaseColor, g_tLmLightColor, g_tLmLightDir либо g_tLightMap.
Количество текстур ShaderDesc находится по +0x38, указатель — по +0x28.
Для дома получены 393 записи, из них 381 с ненулевыми данными потока 8.

## Blender: экспериментальный предпросмотр

```powershell
& 'D:\SteamLibrary\steamapps\common\Blender\blender.exe' --background 'D:\TLOUPS4\EditorFixedAustin\scene_materials_uv_fixed.blend' --python-exit-code 1 --python tlou_extractor/blender_static_lighting.py -- --lighting 'D:\TLOUPS4\StaticLighting\house\lighting.json' --output 'D:\TLOUPS4\StaticLighting\house_static_preview.blend'
```

Нужна сцена нашего экспортёра с `nd_type` и `nd_level_id`. Сопоставление использует
геометрию float32 и полное имя меша, а не близость в пространстве. Исходная сцена
не перезаписывается. Результат содержит отчёт в Text Editor → STATIC_LIGHTING_README
и соседнем `.lighting_report.json`.

BC6H читается Blender в float и сохраняется в EXR; HDR не проходит через PNG.
Предпросмотр использует Emission, отключает лампы и освещение окружения. Откройте
Material Preview или Rendered. Exposure +3 — настройка просмотра, она не изменяет
извлечённые числа. Обновлённый `blender_streaming_tools.py` сохраняет Material Preview
при регистрации сцены с освещением; его можно запускать для панели переключения чанков.

**Формула освещения пока не восстановлена точно.** В предварительном варианте
используется `albedo * (base + direct * max(dot(normal, direction), 0))`. Назначение
потоков 8/9/10 и преобразование направления являются проверяемой гипотезой.
Исходные компоненты доступны как POINT-атрибуты `ND_StreamN_C`; приблизительная
освещённость — `ND_StaticIrradiance`. Никакие значения не заменены этой гипотезой.

Световая карта подключается только для непустого потока 5 в диапазоне [0,1]
и полного набора трёх карт. Это критерий предварительного просмотра, а не
доказательство режима исходного шейдера. Ненормализованные координаты сохраняются
без wrapping. Карта indirect.rgbmax извлекается, но не интерпретируется как RGBM
без подтверждённой формулы. Остальные меши используют предварительное освещение
по вершинам. Объекты без соответствующей записи перечислены в отчёте: освещение
для них не выдумывается. Динамические персонажи, пробники, лампы и динамические
тени в этот проход не входят.

Для полной реконструкции ещё нужно определить выбор шейдерного режима, кодировку
ненормализованного потока 5, точную формулу направленного базиса и RGBMax.
Это отдельный переносимый sidecar; основной игровой экспорт TLVL пока не
сериализует все эти потоки. Переименовывать непроверенные координаты в Lightmap
и считать их готовыми для движка нельзя.
