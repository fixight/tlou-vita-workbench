# Остин: Blender как редактор уровня

## Начало работы

Новые экспорты локаций автоматически включают доступные исходные данные
статического освещения. `.blend` открывается в Material Preview с предварительно
восстановленными материалами; карты HDR и потоки лежат в `static_lighting`.
Точная формула пока экспериментальная, покрытие записано в
`static_lighting_report.json`. Подробнее — в соседнем `STATIC_LIGHTING.md`.
FBX не сохраняет сложную схему световых узлов полностью; для готового освещения
используйте `.blend`. Обновлённый инструмент стриминга сохраняет Material Preview
в сценах с освещением.

1. Откройте `scene_streaming_preview.blend`, если он есть, иначе
   `scene_editor.blend` или `scene.blend`. Это мастер-сцена, не единый уровень для памяти Vita.
   Геометрия разбита на коллекции `LEVEL_<level_id>`, коллизии — отдельно.
   Полная сцена Остина первоначально показывает интерьер дома; остальные уровни
   сохранены в сцене, но скрыты. Не запекайте одновременно все варианты LOD.
2. Перейдите в Scripting, выберите текст `blender_streaming_tools.py`, нажмите
   Run Script / Alt-P. В боковой панели 3D View (N) появится вкладка TLOU.
   Повторный запуск допустим. Никакого включения автоматического запуска
   скриптов для всех .blend не требуется.
   После запуска появляется сообщение с количеством мешей и областей.
   Инструмент расположен в боковой панели именно 3D View, а не Text Editor:
   наведите курсор на окно сцены, нажмите N и выберите вкладку TLOU.
   Открытая сцена уже показывает только дом, поэтому повторный запуск скрипта
   может не изменить изображение. Сообщение также сохраняется в тексте
   `TLOU_EDITOR_STATUS.txt` и выводится в System Console с префиксом [TLOU].
   Выбирайте участок в списке и нажимайте «Приблизить участок». Коллизии,
   области стриминга и сценарные области включаются отдельными переключателями.
   По умолчанию они скрыты; при включении отображаются каркасом.
   «Служебная геометрия» показывает меши с материалами shadowblocker и
   default-collision-color. Они сохранены для экспорта и запекания.
   Просмотр начинается в Solid с текстурами, без затрат Material Preview.
   После импорта FBX откройте соседний `blender_streaming_tools.py` в Text Editor
   и нажмите Alt-P: скрипт восстанавливает отображение по Custom Properties.
   При импорте FBX оставьте включённым Import Custom Properties.
   Повторный запуск скрипта сбрасывает только предпросмотр к начальному участку.
3. Выберите родителя области стриминга. «Набор (вручную)» и «Показать выбранный
   набор» включают выбранные уровни во viewport и рендере. Это просмотр одного
   исходного набора, не симуляция сюжета и не объединение соседних областей.
4. Запекайте нужную геометрию. UV для lightmap назовите `Lightmap`. Базовые UV
   экспортируются из первого UV-слоя. Бaked-изображения, их назначение и
   преобразование текстур в формат Vita остаются задачей вашего asset compiler.
5. Кнопка «Экспорт уровней + стриминга» просит выбрать выходную папку.
   В эту папку пишет `<level_id>.bin`, `level_files.json`, `streaming.bin`
   и читаемый `streaming.json`. Все помеченные визуальные меши и коллизии
   экспортируются, даже скрытые предпросмотром. Мастер-сцену сохраните отдельно.

Для обычного уровня кнопка просмотрщика «Экспорт в Blender + FBX» выдаёт ZIP
с .blend, FBX, областями, таблицами и этим руководством. Соседняя геометрия
не добавляется этим действием автоматически: смотрите coverage. Полный пакет
Остина строится отдельно командой:

```text
python -m tlou_extractor.export_austin_editor --output editor_exports/austin_editor
```

Повторную сборку запускайте в новую папку: существующий `scene.blend` команда
не перезаписывает, чтобы не уничтожить ваши правки и запекание.

## Объекты и редактирование

### Качество текстур

`scene_textures_hq.blend` — версия Остина с исходным максимальным разрешением
доступных текстур (обычно 512–2048 вместо резидентных 64×64). PNG лежат рядом
в `texture_sources_hq`; сохраняйте эту папку вместе со сценой. Текстуры не
уменьшены, Simplify выключен, размер и сжатие можно менять своим пайплайном.
`texture_hq_validation.json` содержит размеры изображений и результаты проверки.

Solid/Texture показывает активный цветовой image node; инструмент теперь
выбирает его автоматически. Для проверки прозрачности и шейдерных эффектов
используйте Material Preview либо Rendered: Solid не воспроизводит материал
игры. Импостеры могут дополнительно требовать маску прозрачности, выбор кадра
атласа и ориентацию к камере; замена мелкого mip не реализует эти шейдеры.
Старая карта `basis1_lightColor` сохранена отдельно от библиотеки HQ; некоторые
материалы исходной сцены ещё требуют восстановления их специальных слотов.

Новые экспорты выбирают максимальную доступную версию по точному хешу;
отсутствующий хеш не заменяется текстурой с похожим названием. Неподдерживаемый
формат теперь вызывает ошибку вместо предположения DXT1. Общий DDS-декодер
исправляет обработку BC3 и BGRA, LightColor не назначается как albedo.

### Пошаговый просмотр стриминга

В панели TLOU есть блок «Пошаговый просмотр стриминга». Первое нажатие
«Следующие чанки» включает первый набор; следующие нажатия переходят дальше.
«Назад» возвращает предыдущий шаг, список «Шаг» позволяет перейти напрямую.
«Вариант N» и «Применить» выбирают один из исходных наборов выбранной области.
Доступные N перечислены в панели; неподдерживаемый N не меняет отображение.
«Перемещать обзор к области» переносит центр обзора к родителю области.

Для Остина задан **ручной маршрут предпросмотра** из 14 шагов: дом, пригород,
дорога, город, переулок, выход к лесу. Это удобный тур по геометрии, а не
извлечённый порядок срабатывания оригинальных триггеров. В других сценах без
Остина области перечислены в порядке метаданных, который также не считается
порядком сюжета. Наборы display/resident_only берутся из файлов без добавления
произвольных чанков; условные селекторы не исполняются, их N выбирается вручную.

Панель показывает появившиеся/скрывшиеся чанки и количество оставшихся.
Полные списки находятся в Text datablock `TLOU_STREAMING_PREVIEW.json`:
`shown/hidden` — изменения реально видимой геометрии сцены;
`request_load/request_unload` — разность требуемых наборов display+resident_only
для двух шагов; `resident_only` — предзагрузка без отображения.
`without_visual_geometry` включает ссылки на контейнеры, аудио, персонажей
и другие ресурсы без визуальных мешей в этой статической сцене.

Режим переключает видимость уже загруженных объектов, **не читает чанки с диска
и не освобождает их память в Blender**. Он не измеряет скорость стриминга Vita
и не моделирует перекрытие областей, сюжетные события или политику выгрузки
оригинального движка. Скрытая геометрия продолжает участвовать в бинарном
экспорте. Переход на обычный выбор «Участок» выходит из пошагового режима.

- `nd_type=visual/collision`, `nd_level_id`: владение мешем конкретным уровнем.
  Сохраняйте эти свойства при объединении/замене мешей. Не объединяйте разные
  level_id в один меш: тогда нельзя корректно выгружать их по отдельности.
- Родитель `streaming_region` либо `gameplay_region` хранит `nd_region_id`.
  Дочерние `region_volume` содержат геометрию области. Можно двигать, вращать,
  масштабировать родителя и редактировать вершины: экспорт учитывает мировую
  матрицу и модификаторы. Объёмы скрыты из рендера и не участвуют в запекании.
- «Добавить объёмы ранней загрузки» копирует исходные объёмы, увеличивая каждый
  на 20% как стартовый пример. Их положение и размер нужно настроить по
  измеренному времени загрузки. Они помечены `nd_role=prefetch`; исходные
  объёмы отображения сохраняются. Эти 20% не являются гарантированным запасом.
- `TLOU_STREAMING_DATA` хранит таблицу областей и наборов. Не удаляйте его.
  Метаданные также есть в Text datablock `streaming.json` и отдельном JSON.
  Custom Properties проходят FBX; .blend удобнее, поскольку сохраняет коллекции,
  встроенный инструмент и настройку редактора.
- Для нового произвольного триггера расширьте схему/экспортёр. Копирование
  родителя без назначения нового ID намеренно вызывает ошибку экспорта.

## Формат бинарников для своего движка

Это простой открытый обменный формат, **не** готовый формат существующего
движка и не оптимизированные Vita-буферы. Никакого executable-кода внутри нет.
Всё little-endian, координаты в оригинальном мире Y-up.

### TLVL — один уровень

16-байтный заголовок: `char magic[4]="TLVL"; uint32 version=1; uint32 jsonBytes;
uint32 dataBytes;`. Затем UTF-8 JSON указанного размера, затем бинарный блок.
JSON содержит level_id, список мешей/материалов, byte offset и corner_count.
Смещения относительны началу бинарного блока. Каждые три записи — треугольник.
Одна запись: 10 float32 (40 байт): position XYZ, normal XYZ, UV0 XY, LightmapUV XY.
Трансформации применены. При отрицательном determinant меняется winding.
Индексация/дедупликация не выполняются: так сохраняются UV-швы и split normals;
для Vita следует переупаковать/индексировать данные под свой renderer.
`type=collision` отделяет оригинальные треугольники коллизии от visual.
`has_lightmap_uv=false` означает отсутствие UV Lightmap, а не готовое запекание.
`image_references` — имена изображений в Blender, не готовые пути GPU-текстур.

### TLST — стриминг и области

12-байтный заголовок: `char magic[4]="TLST"; uint32 version=1; uint32 jsonBytes;`.
Далее ровно jsonBytes байт UTF-8 JSON. Парсер может читать его один раз при
загрузке мира и преобразовать в свои структуры; это не сериализация сырых
C++-структур. Рядом сохраняется читаемый эквивалент `.json`.

У региона есть id, type, source_level, мировые вершины/грани `shapes`, отдельно
`prefetch_shapes`, варианты `sets` (display/resident_only), selector и исходные
свойства/события. AABB служит только broad phase; для точного попадания нужна
проверка формы. Для составных областей сохранено предупреждение о пока не
проверенных правилах объединения оригинала.

## Схема работы движка

1. Прочитать TLST и level_files.json; связать level_id с файлами уровней.
2. Предзагрузка: при приближении/попадании в prefetch загружать допустимые
   будущие наборы с учётом лимита памяти. Подготовка GPU-ресурсов тоже входит
   во время загрузки. Не показывать сразу объединение всех вариантов.
3. Отображение: проверить исходную область, получить N от селектора и
   применить соответствующий display-набор; resident_only не отображать.
4. Переключение делать только после готовности обязательных ресурсов.
   Пакет, ещё нужный другой активной области/зависимости, не выгружать.

**Предел готовности:** 10 мировых селекторов пролога постоянны, 5 зависят от
игрового состояния. Их инструкции извлечены, но привязки запросов состояния,
overrides, пересечения областей и оригинальная политика выгрузки ещё не
полностью воспроизведены. `runtime_ready=false` сохранён намеренно. Для теста
прогулки можно явно задавать N вручную; это не точная симуляция оригинала.
Сценарные персонажи, движение машин, катсцены и освещение автоматически не
воспроизводятся. Смотрите `build_report.json`, coverage и warnings: наличие
манифеста/ссылки не гарантирует наличие всей геометрии или поведения.

Не загружайте все PAK подряд в браузер ради полного города. Используйте пакет
Остина или собирайте нужные уровни частями. Обычный браузерный экспорт теперь
передаёт отдельные меши, чтобы не создавать одну гигантскую JSON-строку.


## Предпросмотр по позиции игрока

В панели TLOU добавлен объект игрока и автоматическая проверка объёмов.
Инструкция и границы эмуляции: [BLENDER_PLAYER_PREVIEW.md](BLENDER_PLAYER_PREVIEW.md).
Общий алгоритм геометрии и ресурсных наборов находится в `tlou_extractor/region_runtime.py`;
при экспорте он встраивается в .blend вместе с панелью.
