# Экспорт Blender → текущий TLOU_Vita

Откройте сцену редактора, загрузите `tlou_extractor/blender_vita_export.py` в Text Editor
и нажмите Alt-P. В 3D View: N → Vita → «Экспорт в TLOU Vita».
Скрипт также лежит в `D:/TLOUPS4/AustinStaticLighting/blender_vita_export.py`
и в папке `tools/blender` проекта движка. Новые сцены редактора включают его как Text.

В диалоге выберите папку и область экспорта: все, видимые или выделенные визуальные
объекты. Скрытые оригинальные коллизии соответствующих `nd_level_id` экспортируются
в любом режиме. Коллизии читаются из объектов `nd_type=collision` или `collision=true`,
без генерации по визуальной сетке, без упрощения и без применения модификаторов.
Визуальные модификаторы применяются. Персонажи со скелетным модификатором отклоняются.

По умолчанию включён адаптивный KD-батчинг: геометрия объединяется по фактической
текстуре внутри одного `nd_level_id`, затем делится по X/Y/Z. Между чанками
геометрия не объединяется. Лимит 4500 треугольников на батч строгий, даже при
совпадающих центрах треугольников. Целевой размер 170 м и минимальный разнос
центров 5 м доступны в настройках. Размер проверяется по вершинам, а не только
центрам. Несколько длинных граней с близкими центрами могут превышать целевые 170 м,
но всегда проверяется диапазон int16. Доступен прежний режим «По объектам».
Свойство объекта `nd_batch_exempt=true` исключает его из объединения с соседями.
Свет, UV и нормаль хранятся на углах треугольника и сохраняются после объединения.

Поле «Размер текстур» по умолчанию 0, то есть исходное разрешение; можно выбрать
64/256/512 и т. п. Уменьшение билинейное, с сохранением пропорций. Принудительного
64×64 из старого скрипта больше нет. Pillow не требуется: используются bpy и numpy.

Кнопка по умолчанию экспортирует в `D:/VitaEngine/app0/exports/build_ДАТА_ВРЕМЯ/`.
Каждый запуск создаёт новую папку сборки. Структура:

```
build_.../
  level.bin
  assets/
    models/
    textures/
    levels/       # отдельные чанки для будущего стриминга
    metadata/     # отчёты, список чанков, TLST при наличии
```

Основной `level.bin` существует всегда и содержит всю выбранную геометрию
и коллизию, в том числе при экспорте нескольких чанков. Отдельные LVL5 на чанк
сохраняются дополнительно в `assets/levels`.
Скопируйте **содержимое** папки сборки в каталог, упаковываемый как `app0:`:
для существующего проекта это `/home/TLOU_Vita/assets`.
Получатся `assets/level.bin`, `assets/assets/models/*.bin`, `assets/assets/textures/*.bin`.
Экспортёр не перезаписывает рабочие ассеты движка автоматически.
Список отдельных чанков лежит в `assets/metadata/level_files.json`.
Текущий движок загружает `app0:/level.bin`, то есть все выбранные при экспорте чанки:
переключение чанков и чтение TLST ещё нужно подключить в StreamManager.

## Формат и координаты

Little endian. Меш: `uint32 vertexCount`, затем треугольники без индексов.
Вершина: `RGBA uint8[4]`, `XYZ int16[3]`, `UV float16[2]`, `octNormal int8[2]`.
Итого 16 байт, точное соответствие `System/DataLoader.h` и `Engine/Render.cpp`.
UV не нормализуются и не ограничиваются 0..1: тайлинг сохранён.
Каждая грань/материал сохраняет разрывы UV, нормалей и цветов.

Blender `(x,y,z)` → движок `(x,z,-y)`; мировые координаты в метрах.
Вершины центрируются внутри группы и переводятся в сантиметры; центр сохраняется
в колонке переноса column-major матрицы GLM. Рендерер уже умножает позицию на .01.
Максимальная ошибка округления 5 мм по оси. Группы делятся при диапазоне >655 м
или >60000 вершин, треугольник с ребром вне представимого диапазона отклоняется.
AABB учитывают ошибку округления. Отрицательный масштаб корректирует обход граней.

Текстура: `uint32 width,height,dataSize`, затем RGBA8 без mipmaps/сжатия.
Исходное разрешение сохраняется. Одинаковые байты имеют одинаковые имена по хешу.
Экспортируется albedo из входа Base Color Principled; нормали/световые атласы
не выбираются как albedo. Процедурные/преобразованные графы требуют предварительного
запекания в изображение и UV. Для константного цвета создаётся текстура 1×1.

LVL5: magic, instanceCount, collisionTriangleCount, lightCount=0,
spawn XYZ+yaw; оригинальные коллизии float32[9] на треугольник;
затем инстансы: matrix float32[16], AABB float32[6], две строки UTF-8
с длиной uint16 (модель, текстура). Коллизия мировая, точность float32.
PlayerStart ищется по имени или `nd_type=player_start`; yaw задаётся
свойством `spawn_yaw` в градусах, а без свойства берётся горизонтальное направление
стрелки (для обычного Empty — локальная +Y). Это учитывает наклон -90° старого маркера.
Поддерживаются имена PlayerStart, PLAYER_START и SpawnPoint. Кнопка создания ставит
маркер в 3D Cursor. При отсутствии старт `(0,1,0)` и yaw=0.
В панели N → Vita теперь есть явное поле «Маркер спавна». Поддерживается также
имя Player Spawn; при нескольких маркерах нужно выбрать нужный. Кнопка экспорта
не допускает молчаливую замену отсутствующего маркера на `(0,1,0)`.
Низкоуровневый вызов export_vita без require_spawn=True сохраняет прежний fallback
для программных тестов. Позиция берётся из evaluated matrix_world, учитывает
родителей и constraints. Выбранный объект сохраняется ссылкой и переживает переименование.
Отчёт содержит spawn.object, spawn.position, spawn.yaw и spawn.fallback.

Поведение камеры и персонажа в движке сохранено исходным. Экспортёр записывает
позицию и yaw в существующие поля LVL5, которые читает DataLoader::LoadLevel.
Установка камеры, смещения персонажа и применение yaw определяются кодом движка.

## Освещение

По умолчанию используется `ND_StaticIrradiance`. Для нативных directional-атласов
экспортёр семплирует base/direct/direction в ND_LightingUV в углах треугольников
по формуле импортированного предпросмотра. Остальные поверхности используют
атрибут света POINT или CORNER. HDR обрезается до диапазона RGBA8; количество
обрезанных углов записывается в `assets/metadata/vita_export_report.json`. Формула нативного света
пока экспериментальная и не гарантирует точное совпадение с оригинальной игрой.
Если выбран стандартный ND_StaticIrradiance, а его нет, используется старый `Col`.
Произвольное первое цветовое поле больше не выбирается: это могло быть служебное поле.

Собственное запекание может записывать RGB освещения в любой Color Attribute
типа FLOAT_COLOR или BYTE_COLOR. Укажите его имя в поле «Атрибут света».
Цвет содержит освещение, **без повторного умножения на albedo**. Множитель света
позволяет уменьшить HDR перед упаковкой. Объекты без атрибута получают белый свет
и перечисляются в отчёте. Экспортёр не запускает запекание в движке или Cycles.

Световые текстуры не экспортируются. Текущий шейдер умножает albedo × цвет вершины
× 1.45, не применяет sRGB-декодирование. Поэтому соответствие цветов Blender
не абсолютно; множитель 1/1.45 компенсирует только дополнительную яркость.
Тени между редкими вершинами могут терять детали: при необходимости увеличьте
плотность сетки до запекания.

Отдельная маска прозрачности добавляется в alpha albedo, но текущий шейдер движка
не делает alpha-test/blend. Это потребует отдельной поддержки материалов в рендерере.

Если сцена содержит встроенный `blender_streaming_tools.py`, также сохраняется
TLST `assets/metadata/streaming.bin` и JSON с уже существующими объёмами и привязкой файлов чанков.
Это данные редактора; текущий DataLoader их не читает автоматически.
