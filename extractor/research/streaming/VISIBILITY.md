# База выбора отображаемых уровней

Продолжение с работающим выбором по позиции/сюжету и экспортом TLTR:
[RUNTIME.md](RUNTIME.md). Ограничения ниже описывают предыдущий этап исследования.

Продолжение исследования REGION_TREE: сверка с исполняемым файлом из образа
пользователя, а не предположение по названиям свойств.

## Что доказано кодом

В `eboot.bin` по файловому смещению `0x79e390` находится функция обработки
областей загрузки. Она запрашивает области категории `camera` (ID `0x89335b6e`),
проверяет пространственное условие, затем получает целочисленный результат
обработчика `0xf131b5e1`. При отсутствии обработчика используется 1; результат
<= 0 пропускает область. Точный контракт пространственного запроса пока отдельно
не воспроизведён. Существуют также override-наборы; их ветка не реализована.

Далее оригинальный код форматирует строки `level-%d`, `level-no-display-%d`
(`0x79e4c6`, `0x79e501`) и вычисляет их ID. Для N=1 также принимает старые
ключи `level` и `level-no-display`. Ключ `0x4f807b48` учитывается при любом
положительном N и попадает в ветку display. Его исходное имя неизвестно.

Уровни обоих видов добавляются в один список; различается флаг в записи
(`0x79e5db`–`0x79e668`). Повторный no-display снимает этот флаг
(`0x79e6b2`), а повторный display обратно его не устанавливает. Мы сохраняем
эту политику внутри одного набора. Глобальное объединение нескольких областей
и полный жизненный цикл уровня ещё не воспроизведены.

**No-display не следует трактовать как отключение всего уровня:** поведение
звука, сценариев и коллизий отдельно не исследовано. Речь о флаге отображения,
а не о полном разделении resident/active всех подсистем.

Восстановлен hash строк: CRC32 MSB-first, polynomial 0x04c11db7, initial 0,
final xor 0. Код `0xc73440`, таблица `0x11a1880`. Все 15 исходных ID имен
мировых областей совпали с вычисленными. Это позволяет точно читать
`level-1..4` и `level-no-display-1..4`, а не назначать смысл произвольным числам.

## Конкретный пример: regionshape-4747 (дом)

| Результат селектора | Полный интерьер | Упрощённый интерьер |
|---|---|---|
| 1 | display | no-display |
| 2 | отсутствует в прямом наборе | display |
| 3 | display | no-display |

«Отсутствует» не равнозначно немедленной выгрузке: ресурс может требоваться
другой областью или зависимостью. Кеши также являются уровнями-контейнерами;
их присутствие в display-списке не означает наличие собственной геометрии.

Селекторы десяти мировых областей буквально возвращают 1. Оставшиеся пять
содержат ветвления, вызовы сценарных и нативных функций. Восстановлены все
использованные ими инструкции, но не реализация вызываемых функций.
В `bin.psarc/dc1/tasks.bin` найдены строки с точными ID аргументов:
`home`, `hom-house-daughter-room`, `hom-house-escape`, `hom-town-crash`,
`hom-road-highway`, `hom-road-freeway-traffic`, `hom-alley-bar-enter`,
`hom-alley-bar-split-up`, `hom-alley-clear`.

Хеши двух вызываемых функций совпали с кандидатами `before-task?`
(`0x4d2bf414`) и `task-complete?` (`0xf1360136`). Эти написания подобраны
по хешам, а не найдены как исходные имена; семантика самих функций ещё требует
проверки. Нативные `object-spawned?` и `get-boolean` сопоставлены с реальными
строками в eboot. Для части ID объекта/флага человекочитаемые имена не найдены.

## Экспорт и исполнение

`output/world-home-visibility.json` содержит для каждой области:
- все обнаруженные варианты прямых display/no-display наборов;
- точные level-id и их оригинальные манифесты (пакеты, акторы, зависимости);
- разобранные инструкции селектора с ID вызываемых функций и аргументов;
- нераспознанные строковые свойства, без молчаливого включения/исключения.

Осталось одно строковое свойство мира вне классификации:
`regionshape-7267`, `0xcb55fbef`, `mil-puddle-water`. Оно не входит в проверенную
ветку выбора direct levels; назначение пока неизвестно.

`visibility_base.py` предоставляет `select_levels` и ограниченный
`evaluate_selector`. Последнему нужно явно передать реализации запросов
игрового состояния. Неизвестный запрос вызывает ошибку, не выбирает вариант 1
по умолчанию. Пять вариантов входных данных для реального селектора дома
проверены тестами, включая оба пути возврата 2 и возвраты 1/3.

```text
python -m research.streaming.visibility_base
python -m unittest tests.test_streaming_visibility -v
```

Сохранён относящийся к исследованию дизассемблированный код:
`output/eboot_region_selection.asm`. Адреса в нём — смещения в файле данного
eboot, не виртуальные адреса ELF и не универсальные адреса других версий.

## Как применять к Vita

Разделить в будущем раннюю загрузку данных и оригинальное решение о показе.
Для предварительной загрузки использовать соседние объёмы и допустимые будущие
варианты, ограничивая их бюджетом памяти; не показывать сразу объединение всех
вариантов (полный и упрощённый интерьер могут перекрываться).

Момент старта чтения можно выбирать по измеренному времени чтения,
распаковки и создания GPU-ресурсов. Сравнение скорости носителя само по себе
не задаёт нужный запас. Переключать отображение следует только когда все
обязательные ресурсы целевого набора готовы.

Это пока база для интеграции, а не готовый стример: ещё нужны проверка
семантики запросов сценарного состояния, overrides, пересечения областей,
глобальные зависимости и правила безопасного удержания/выгрузки.
