# REGION_TREE: результаты исследования PS4 TLOU Remastered

Текущий результат для экспорта чанков и C++: [RUNTIME.md](RUNTIME.md).
Ниже сохранён первоначальный исследовательский этап; пространственная сетка,
объединение объёмов, порядок выбора и условия задач уже разобраны в новом модуле.

Исследованы реальные PAK из `D:\TLOUPS4\Extracted\pak32` и манифест
`pak32.txt` из указанного пользователем образа. Это исследовательский экспорт,
а не готовая реализация оригинального стриминга.

Последующее исследование кода игры расшифровало выбор display/no-display
наборов и структуру селекторов: см. [VISIBILITY.md](VISIBILITY.md).
Описанные ниже неизвестные свойства относятся к первоначальному этапу.

## Что извлечено

| Файл | Области | Составляющие объёмы | Записи событий | Свойства |
|---|---:|---:|---:|---:|
| world-home-ingame14.pak | 15 | 34 | 15 | 820 |
| hom-house-interior-ingame14.pak | 35 | 47 | 25 | 57 |
| hom-road-suburb-ingame14.pak | 3 | 4 | 2 | 7 |

В `world-home` 95 уникальных строк, похожих на ссылки на ресурсы (после
исключения ключа заголовков секций `0x54727bcd`). **Все 95 имеют точное
совпадение `level-id` в оригинальном pak32.txt.** Зависимости этих уровней
сохранены в `output/manifest_dependencies.json`.

Связь `область → свойства → имя ресурса` читается по указателям с PAK
relocation fixups, а не восстанавливается по соседству строк в файле.

Например, `regionshape-4747` содержит ссылки на `hom-house-interior`,
`hom-house-interior-low`, `hom-house-yard`, `hom-house-interior-script`,
кеши дома/дороги/города и другие ресурсы. Разные свойства могут ссылаться
на один ресурс: для `hom-house-interior` ключи `0xdf0bad70` и `0xd689961e`,
для `hom-house-interior-low` ещё `0xd2488ba9`, `0xb7747086`, `0xbef64be8`.
Это нельзя сворачивать в один безусловный список загрузки.

Внутри дома есть именованные области телефона, комнаты Джоэла, спуска вниз,
испуга у окна, полицейской машины, выхода из спальни. Также обнаружены
`hom-house-runtime-light-switch-1` … `-7` и области отражений. Название
помогает выбрать объект для проверки, но не доказывает поведение события.

## Восстановленный формат (проверенные файлы)

Все смещения ниже относительно соответствующей записи. Числа little-endian;
указатели разрешаются через PakFile.read_ptr и таблицу fixups.

REGION_TREE:
- `+0x20`: указатель на пространственную структуру, пока не разобрана.
- `+0x28`: inline-массив указателей на области, заканчивающийся нулём.

Область:
- `+0x00`: указатель на имя; `+0x08`: необъяснённый 32-битный ID.
- `+0x28`: указатель на первый элемент связного списка объёмов.
- `+0x30`: uint16 число свойств; `+0x32`: uint16 число записей событий.
- `+0x38`: указатель на записи событий по 16 байт.
- `+0x40`: указатель на свойства по 16 байт.

Свойство: uint32 ключ, uint32 тип значения, 8 байт значения. Тип 3 содержит
указатель на строку. Тип 4 сохраняется как сырые данные без назначения смысла.
Записи событий сохраняются с исходными ключами и указателями на payload;
интерпретатор событий не реализован.

Объём:
- `+0x00`: следующий объём или null.
- `+0x10`: uint16 тип (во всех проверенных объёмах 1).
- `+0x12`: uint16 число граней.
- `+0x20`: грани по 0x70 байт.

Грань:
- `+0x00`: 16 float, преобразование world → face.
- `+0x40`: 4 float, нормаль (XYZ совпадают с третьим столбцом матрицы).
- `+0x50`: четыре пары float — координаты четырёхугольника в плоскости грани.

Для восстановления вершин: `world = [u, v, 0, 1] @ inverse(matrix)` при
представлении 16 float как четырёх последовательных строк. Вывод — в родных
мировых координатах, Y вверх. Грани каждого объёма восстановлены независимо.

## Проверки и ограничения

- В world-home максимальное расхождение ближайших копий углов между гранями:
  0.000145415 единицы; в hom-road-suburb: 0.000025419.
- В доме одна область, `hom-rs-house-joel-room-1`, имеет швы до 0.012067 единицы.
  Это явно отмечено в JSON. Возможно, связано с неплоскими исходными гранями;
  причина пока не доказана. Остальные объёмы дома проходят порог 0.002.
- OBJ сохраняет отдельно восстановленные грани без сварки или исправления швов.
- Порядок областей в файле **не** принят за порядок прохождения.
- Не установлены значения ключей загрузки/выгрузки, момент входа/выхода,
  приоритет пересекающихся областей и правила объединения нескольких объёмов.
- В bin.psarc проверено наличие DC00-модулей сценариев, в том числе
  `dc1/ss-home/ss-hom-house-escape.bin` и `ss-hom-road-funcs.bin`.
  В первом сохраняются строки состояний initial/setup/igc-escape/complete
  и путь исходного `.dc`. Байткод не декомпилирован.

## Файлы результата

`output/*-ingame14.json`: области, грани, координаты, свойства, исходные
смещения и сырые записи событий. `output/*-ingame14.obj`: объёмы для осмотра
в 3D-редакторе, отдельный объект на составляющий объём. Это исследовательские
поверхности, не коллизии и не готовые исполняемые триггеры.

Воспроизведение из корня проекта:

```text
python -m research.streaming.inspect_regions
```

Следующий этап: установить семантику ключей свойств и событий по использующему
их коду/байткоду, затем проверить набор активных пакетов на конкретной позиции.
Геометрия и точные ссылки на манифесты уже дают основу для такой проверки.
