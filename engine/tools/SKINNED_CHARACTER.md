# Sarah / SK16 v1

Включён существующий `render.render(characters, camera, lights, characterShader, true)`. Контроллер переключает три клипа: idle, walk, run (L). SELECT сохраняет существующий noclip: персонаж и его анимация замирают. Коллизии остаются у существующего Actor. Spawn и камера не менялись. Матрица отображения обновляется после коррекции коллизии.

Новый файл: `app0:/characters/sarah16/sarah.sk16`. Старые sara.bin/saraTex.bin сохранены, но больше не загружаются этим персонажем. Уровень остаётся на прежнем статическом Vertex/LVL5. Скелетные вершины имеют отдельный ABI: int16 XYZ @0, half UV @6, oct snorm8 normal @10, uint8 bone IDs @12, unorm8 first weight @14, reserved @15. Второй вес 1−первый. Шаг 1 мм, origin передаётся на батч; позиция распаковывается ДО скиннинга. Actor имеет масштаб 1, без множителя 0.01 для уровня.

Батчи индексированные (uint16), палитра до 24 матриц mat4 на draw, индексы локальные. Экспорт заранее группирует треугольники по совместимым палитрам: 30 draws, 20 989 вершин с дублированием на границах, 33 505 треугольников. Это полный исходный меш, без LOD и сокращения скелета. Текстуры RGBA8 до 512 px; текущий шейдер использует цвет, alpha-test и два существующих динамических источника, без normal maps.

Файл содержит версию, батчи с путями текстур, палитрами, VBO/IBO, и 3 клипа. Клип содержит 30 Hz матрицы skinning, вычисленные из полной glTF иерархии, для 231 используемой кости. В движке матрицы линейно интерполируются между отсчётами: это первый рабочий проигрыватель, а не финальное quaternion/TRS смешивание анимаций. Переходы между клипами пока мгновенные. Горизонтальный root motion удалён при экспорте, чтобы контроллер не перемещал Сару дважды; вертикальное движение сохранено. Данные анимации около 6.8 MiB, полный пакет около 7.3 MiB; последующая оптимизация возможна.

Экспорт (Python + NumPy + Pillow): `python tools/export_vita_character.py <sarah.glb> <assets/characters/sarah16> --max-texture 512`. Названия трёх клипов сейчас настроены на Сару.

Проверки: `python3 tools/tests/run_skinned_smoke.py` — реальный C++ загрузчик/отсечения повреждённых файлов/GL ABI/индексы/обновление поз; `python3 tools/tests/run_debug_smoke.py` — статический рендер, HUD, noclip и триггеры. Host GL mocks не проверяют исполнение шейдеров Vita и итоговые пиксели.

Исправление видимости: массив матриц запрашивается через `uBones`, затем при -1 через `uBones[0]`. В vitaGL без STRICT_UNIFORMS_COMPLIANCE требуется базовое имя. Отрицательные значения location, кроме -1, могут быть корректными указателями vitaGL. Host-тест моделирует оба режима и отсутствие массива. Фактический рендер проверен в C:/dev/Vita3K/cmake-build-debug/bin/Vita3K.exe; захвачен кадр color surface, Сара видна. Диагностический запуск с включённым surface sync/PNG capture не подходит для оценки FPS.


## Где читать код

Начинай с `Objects/Character.cpp`: `Update()` выбирает Idle, а `HandleMovement()` переключает Walk/Run. В конце вызывается `SkinnedModel::Update()`.

В `Engine/SkinnedModel.cpp`:

- `Load()` координирует загрузку; `LoadBatches()` читает меши и палитры, `LoadClips()` — отсчёты матриц.
- `Update()` ведёт время клипа; `FindFrameSamples()` находит два соседних кадра; `InterpolatePose()` смешивает их матрицы.
- `Draw()` передаёт позу в GPU по батчам. `CopyBonePalette()` выбирает нужные кости, `BindVertexLayout()` описывает 16-байтовую вершину.
- `FindBonePaletteUniform()` содержит особенность поиска массивов в vitaGL. Проверяется именно -1, поскольку другие отрицательные location могут быть корректными.

В `Engine/VitaEngine.cpp` функция main вершинного шейдера персонажа распаковывает позицию, смешивает две матрицы с весами и деформирует позицию/нормаль.

В `tools/export_vita_character.py`: `export()` связывает этапы; `evaluate_world_transforms()` вычисляет иерархию glTF; `select_two_influences()` сокращает веса; `group_triangles_by_palette()` формирует батчи; `pack_mesh_batch()` упаковывает вершины; `bake_animation_clips()` запекает матрицы; `write_character_package()` записывает SK16.

Рефакторинг читаемости проверен host-тестами и компиляцией изменённых объектов VitaSDK. Повторный экспорт совпал побайтово со всеми 12 исходными файлами, включая пакет, текстуры и отчёт. Формат и данные сохранены.
