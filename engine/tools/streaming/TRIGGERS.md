# Области пролога и назначения C++

Каталог: `D:\TLOUPS4\AustinStreaming\prologue_triggers.md` и `trigger_catalog.json`.
Для пролога описаны 205 областей из REGION_TREE, у 88 есть callback.
Каталог охватывает также общие ресурсы, присутствующие в исходном пакете стриминга:
всего 426 областей. Это не 426 сюжетных триггеров Остина.

Сканирование 2147 исходных DC-файлов восстановило дополнительные имена по совпадению
CRC с исходными текстовыми токенами. Сохранены источник и смещение каждого имени.
Для 103 контроллеров пролога собраны исходные подписи состояний/обработчиков.
Они помогают назначить роль области, но не являются последовательностью действий.

Полные аргументы, условия ветвлений, ID, формы/координаты и исходные смещения
находятся в карточках. Unknown-инструкции и отсутствующие имена не заменяются
предположениями. После неизвестной инструкции знание регистров сбрасывается.

## Blender

1. Открыть свежий `D:\TLOUPS4\AustinStaticLighting\blender_native_streaming.py`
   в Text Editor и Run Script. Это обновление сохраняет текущую видимость,
   сюжетный шаг, настройки симуляции и имеющиеся назначения для порта.
2. В N → TLOU включить «Сценарные области», выбрать тип «События и диалоги».
   Для акустики, отражений и эффектов есть отдельные фильтры.
3. Выбрать меш объёма или родительский объект области. Панель покажет
   исходные события и вызовы. «Полная карточка области» создаёт
   `TLOU_TRIGGER_DETAILS.txt`; если Text Editor открыт, переключает его на карточку.
4. Для нашего поведения включить «Использовать назначение», ввести имя обработчика
   C++, например `JoelRoomExplosion`, фазу `enter`, `inside` или `exit`, режим
   однократности и JSON-параметры. Значения параметров задаём для порта;
   они не становятся автоматически извлечённым таймингом оригинала.
5. Экспорт Vita сохраняет назначения в `assets/metadata/trigger_bindings.json`,
   вместе с исходным ID области, именем чанка и отредактированными объёмами.
   Карточки находятся в `trigger_catalog.json`; данные также входят в TLST/JSON.

Наши назначения не подменяют исходные callback. Отключённое назначение не
экспортируется в список действий. Исходная геометрия и описание сохраняются.

## Граница движка

Существующий LVL5 не менялся. DataLoader не начинает автоматически выполнять
действия из JSON. При подключении игровых триггеров движок должен создать
объёмы по координатам native Y-up, определить enter/inside/exit, затем отправить
действие нашему диспетчеру C++. Идентификатор действия — выбранное нами имя;
имя получателя исходного события может относиться к сценарному контроллеру,
а не к видимому мешу. Неразрешённые связи не следует заменять ближайшим объектом.

Однократность, условия задач и точные задержки выполняет наш обработчик.
Каталог не исполняет полный VM Naughty Dog и не утверждает, что эти условия
уже восстановлены для всех областей.

## Повторное извлечение

```powershell
C:\Python314\python.exe -m research.streaming.build_trigger_catalog `
  --bundle D:\TLOUPS4\AustinStreaming\streaming_runtime.json `
  --game-main 'D:\Новая папка (3)\The Last of Us™ Remastered\build\Image0\build\ps4\main' `
  --output D:\TLOUPS4\AustinStreaming
```

Парсер вызовов общий. Для другой главы можно передать её bundle, `--script-prefix`
и `--family`. Пересборка world-home через build_runtime также обновляет каталог.
